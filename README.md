# הנה"ח — אוריאל פינטו

אפליקציית הנהלת חשבונות לעוסק פטור: תיעוד הכנסות והוצאות, שמירת קבלות,
אומדן מס, צ'קליסט מסמכים לדוח השנתי, והפקת חבילה מלאה לרו"ח.

עובדת כולה בדפדפן, ללא שרת. הנתונים נשמרים במכשיר.

## הפעלה

```bash
# כל שרת סטטי מספיק
python3 -m http.server 8000
```

ואז `http://localhost:8000`. אין שלב build.

> פתיחה ישירה של הקובץ (`file://`) לא תעבוד — IndexedDB דורש origin אמיתי.

מומלץ להוסיף את האתר למסך הבית בטלפון: זה משפר את הסיכוי שהדפדפן ישמור על
האחסון לאורך זמן.

## בדיקות

```bash
npm install
npm test
```

בדיקות מקצה לקצה בדפדפן אמיתי (Playwright): הזנת רשומות, שמירה, **הישרדות
רענון**, סינון לפי שנה, שמירת קבלה כ-Blob, גיבוי מוצפן ומחזור שחזור מלא לתוך
פרופיל ריק — כולל שסיסמה שגויה נדחית ואינה מוחקת נתונים.

הבדיקה המרכזית היא "הנתונים שרדו רענון". הבאג שהשבית את האפליקציה — קריאה
ל-API אחסון שלא קיים — עבר בדיקת תחביר בלי בעיה; רק הרצה אמיתית תופסת אותו.

אם הדפדפן כבר מותקן במערכת: `CHROME_PATH=/path/to/chrome npm test`.

לבדיקות הענן נדרש אמולטור Firebase מקומי:

```bash
npm run emulators     # בטרמינל נפרד
npm run test:cloud    # 18 בדיקות כללי אבטחה + 13 בדיקות סנכרון
```

## מבנה

```
index.html                 האפליקציה כולה — HTML, CSS ו-JS בקובץ אחד
icon.png                   אייקון למסך הבית
vendor/                    xlsx, jszip ו-Firebase Auth — מאוחסנים מקומית
firebase/                  כללי אבטחה והקמת סנכרון ענן (אופציונלי)
worker/                    שרת ביניים אופציונלי לסריקת קבלות עם Claude
test/                      בדיקות דפדפן, כללי אבטחה וסנכרון
```

הקובץ היחיד הוא בחירה מכוונת: אין תלויות, אין build, והעלאה לאחסון סטטי היא
העתקת קובץ. `vendor/` מקומי כדי שהאפליקציה תעבוד גם אופליין וגם אם ה-CDN
נחסם — וכדי להסיר סיכון שרשרת אספקה.

## אחסון

הכל נשמר ב-**IndexedDB** בדפדפן, בשלושה object stores:

| Store | תוכן |
|---|---|
| `entries` | הכנסות והוצאות. אינדקסים לפי `date` ו-`type` |
| `files` | קבלות, טפסים ומסמכים — כ-Blob |
| `meta` | הגדרות, צ'קליסט המסמכים, סטטוס שנים |

הסכימה מנוהלת בגרסאות (`DB_VERSION`) עם נקודת מיגרציה ב-`openDB()`, כדי
שאפשר יהיה לשנות מבנה בעתיד בלי לאבד נתונים.

האפליקציה מבקשת `navigator.storage.persist()` כדי שהדפדפן לא ימחק את
האחסון אוטומטית.

### גיבוי — לא אופציונלי

הנתונים קיימים במכשיר אחד בלבד. טלפון שאבד, פורמט, או "נקה נתוני גלישה"
מוחקים הכל, ורשומות מס צריכות לשרוד שבע שנים.

בטאב **סיכום** יש **"גבה הכל לקובץ ZIP"** — קובץ אחד עם כל הרשומות, הקבלות,
הטפסים וההגדרות. **"שחזר מגיבוי"** מחזיר את הכל, גם במכשיר אחר. האפליקציה
מתריעה אם לא גובה מעל 30 יום.

### הצפנת הגיבוי

הגיבוי הוא הדבר היחיד שעוזב את המכשיר, ולכן הוא הנקודה החשופה ביותר: הוא
מכיל טופס 106, אישורי בנק וכל הקבלות. לפני ההורדה נשאלת סיסמה.

- **AES-GCM-256**, מפתח נגזר ב-**PBKDF2-SHA256 עם 600,000 איטרציות**
  (המלצת OWASP), `salt` ו-`iv` אקראיים בכל גיבוי
- GCM מאמת את התוכן: סיסמה שגויה או קובץ ששונה בבייט אחד נכשלים, ולא
  מחזירים זבל
- הסיומת `.hhbak`. השחזור מזהה לבד אם הקובץ מוצפן
- אפשר לוותר על ההצפנה ("בלי הצפנה") — סביר אם הקובץ נשאר במכשיר בלבד

**הסיסמה לא נשמרת בשום מקום.** אם היא אובדת, הגיבוי אינו ניתן לשחזור. שמור
אותה במנהל סיסמאות, לא באותו מקום שבו נשמר הגיבוי.

## סנכרון ענן (אופציונלי)

כבוי כברירת מחדל. כשמופעל — סנכרון בין מכשירים **בהצפנה מקצה לקצה**: כל
רשומה וכל קובץ מוצפנים במכשיר לפני העלייה, ו-Google מאחסן בייטים שאין לו
מפתח אליהם.

- **שתי סיסמאות נפרדות**, וזה מהותי: חשבון Google מזהה מי אתה, וסיסמת
  ההצפנה קובעת מה אפשר לקרוא. השנייה לעולם לא נשלחת לשרת.
- **היררכיית מפתחות** — מפתח נתונים אקראי (DEK) מצפין את התוכן, ונשמר בענן
  עטוף במפתח שנגזר מסיסמת ההצפנה (PBKDF2-600k). שינוי סיסמה עוטף מחדש
  מפתח אחד ולא מצפין מחדש את כל הארכיון.
- ה-DEK נשמר מקומית כ-`CryptoKey` לא-ניתן-לייצוא, כך שהסיסמה נדרשת פעם
  אחת בכל מכשיר.
- **מחיקות מתפשטות כ-tombstones**, אחרת רשומה שנמחקה הייתה חוזרת מהמכשיר
  השני. התנגשויות: last-write-wins לפי `updatedAt`.
- ספריות Firebase (167KB) נטענות רק אם הענן מוגדר בפועל.

⚠️ **איבוד סיסמת ההצפנה = איבוד נתוני הענן.** אין שחזור סיסמה — זה מה שהופך
את ההצפנה לאמיתית. הנתונים במכשיר ובגיבויים אינם מושפעים.

הקמה מלאה: `firebase/README.md`.

## נתוני מס

כל שיעורי המס יושבים ב-`TAX_YEARS` בראש ה-script, בלוק אחד לכל שנה: מדרגות,
שווי נקודת זיכוי, תקרת עוסק פטור, ושיעורי ביטוח לאומי.

שנה שאין לה בלוק מחושבת לפי השנה המוגדרת הקרובה שקדמה לה, והאפליקציה מציגה
על כך אזהרה גלויה.

**כל השיעורים מסומנים כרגע `verified: false`** — הם הועתקו מהמימוש הקודם ולא
נבדקו מול הפרסום הרשמי. לפני הסתמכות: ודא מול רשות המסים וביטוח לאומי,
ואז סמן `verified: true`.

האומדן הוא אומדן. הוא לא מכיר בניכויי פנסיה וקרן השתלמות, ולא בנקודות זיכוי
מעבר למה שהוזן ידנית. המספר הסופי נקבע אצל הרו"ח.

## סריקת קבלות עם AI

כבויה כברירת מחדל. היא דורשת שרת ביניים שמחזיק את מפתח ה-API — אסור להטמיע
מפתח בדף ציבורי. ראה `worker/README.md`, ואז מלא ב-`index.html`:

```js
const AI_ENDPOINT = 'https://hanhac-scan.<שם>.workers.dev';
```

## אבטחה ופרטיות

**הנתונים לעולם לא עוזבים את המכשיר.** אין שרת, אין חשבון, אין סנכרון. הכל
יושב ב-IndexedDB של הדפדפן שלך — מבודד לפי origin ולפי מכשיר.

מכאן נובעת נקודה שחשוב להבין: **כתובת ציבורית אינה דליפת מידע.** מי שיפתח את
הכתובת יקבל אפליקציה ריקה. הנתונים שלך לא שם.

### שכבות ההגנה

| שכבה | מפני מה |
|---|---|
| הצפנת גיבוי (AES-GCM-256) | הקובץ היחיד שעוזב את המכשיר — דליפה מדרייב או ממייל |
| CSP `default-src 'none'` | `connect-src` מונע מקוד זדוני לשלוח מסמכים החוצה |
| אפס תלויות חיצוניות | הספריות מקומיות — אין CDN שיכול להגיש קוד שהשתנה |
| `noindex` | הדף לא מופיע בחיפוש |
| escaping עקבי | תוכן משתמש ותשובות AI לא מוזרקים כקוד |
| מפתח API בצד שרת | ה-Worker מחזיק את המפתח; הדף לעולם לא רואה אותו |
| הצפנת ענן מקצה לקצה | Google מאחסן אך לא יכול לקרוא — המפתח לא עוזב את המכשיר |
| כללי אבטחה ב-Firebase | שכבה שנייה: אפילו העלאת קובץ לא מוצפן נחסמת בשרת |

### מה עדיין באחריותך

- **נעילת מסך במכשיר.** זו ההגנה היחידה מפני מישהו שמחזיק את הטלפון שלך פתוח.
  iOS ו-Android מצפינים את האחסון כשהמכשיר נעול — זה מכסה גם את IndexedDB.
- **סיסמת הגיבוי.** במנהל סיסמאות, ולא באותו מקום שבו שמור הגיבוי.
- **לגבות.** האפליקציה מזכירה אחרי 30 יום; ההצפנה הופכת את הגיבוי לבטוח
  לשמירה בדרייב.

### הערות למי שמארח

- `frame-ancestors` ו-`X-Frame-Options` פועלים רק ככותרות HTTP ולא כתגית
  `meta`. אם האחסון מאפשר כותרות מותאמות — כדאי להוסיף אותם.
- אם מגדירים `AI_ENDPOINT`, יש להוסיף את מקור ה-Worker ל-`connect-src`
  ב-CSP, אחרת הבקשה תיחסם.
