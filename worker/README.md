# שרת ביניים לסריקת קבלות

Cloudflare Worker שמחזיק את מפתח ה-API של Anthropic ומאפשר לאפליקציה לסרוק
קבלות בלי לחשוף את המפתח.

## למה זה נחוץ

מפתח API בדף סטטי הוא מפתח פומבי — כל מי שפותח DevTools רואה אותו ויכול
להשתמש בו על חשבונך. בנוסף, קריאה ישירה מהדפדפן ל-`api.anthropic.com` נחסמת
על ידי CORS. ה-Worker פותר את שתי הבעיות: המפתח נשאר בצד השרת, והדף שולח
לכתובת שלך בלבד.

## פריסה

```bash
cd worker
npm install

# המפתח נשמר כ-secret ולא בקוד ולא ב-wrangler.toml
npx wrangler secret put ANTHROPIC_API_KEY

npx wrangler deploy
```

בסיום הפריסה מתקבלת כתובת בסגנון `https://hanhac-scan.<שם>.workers.dev`.

## חיבור לאפליקציה

ב-`index.html`, מלא את הקבוע:

```js
const AI_ENDPOINT = 'https://hanhac-scan.<שם>.workers.dev';
```

עדכן גם את `ALLOWED_ORIGINS` ב-`wrangler.toml` לכתובת שבה האפליקציה מתארחת,
ופרוס מחדש. בלי זה ה-Worker יחזיר 403 לכל בקשה.

## הגנות מובנות

| הגנה | מה היא עושה |
|---|---|
| `ALLOWED_ORIGINS` | רק הדומיינים שברשימה יכולים לקרוא ל-Worker |
| מגבלת גודל | דוחה קבצים מעל 5MB לפני שהם מגיעים ל-API |
| בדיקת `media_type` | רק JPEG, PNG, WebP ו-PDF |
| שגיאות אטומות | גוף השגיאה של ה-API לא מוחזר ללקוח |

## על המימוש

- **מודל:** `claude-opus-5` עם adaptive thinking.
- **פלט מובנה:** התשובה נאכפת מול סכימת Zod דרך `messages.parse`, כך שהיא
  תמיד JSON תקין. אין צורך לנקות ` ```json ` או לפרסר טקסט חופשי — זו הייתה
  נקודת הכשל השברירית ביותר במימוש הקודם.
- **`stop_reason: "refusal"`** מטופל בנפרד ומוחזר כ-422.
- **טיפול בשגיאות** מהספציפי לכללי, כדי לא לאבד את ההבחנה בין שגיאה שכדאי
  לנסות שוב (429, 5xx, רשת) לבין כזו שלא (400, 401).

## עלות

סריקה בודדת של קבלה היא בקשה קטנה. אם השימוש יהיה כבד, `claude-sonnet-5`
יעבוד לא פחות טוב למשימת חילוץ פשוטה כזו ובעלות נמוכה יותר — שנה את שדה
`model` ב-`src/index.js`.
