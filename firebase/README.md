# סנכרון ענן — הקמה

סנכרון בין מכשירים **בהצפנה מקצה לקצה**: Google מאחסן את הנתונים אך לעולם
לא יכול לקרוא אותם. ההצפנה נעשית במכשיר לפני כל העלאה, והמפתח לא נשלח
לשרת בשום שלב.

הענן אופציונלי לחלוטין. בלי ההקמה הזו האפליקציה עובדת בדיוק כמו קודם —
מקומית בלבד.

## שתי הסיסמאות — ההבדל החשוב ביותר

| | מה היא עושה | לאן היא מגיעה |
|---|---|---|
| **חשבון Google** | מזהה מי אתה | ל-Google |
| **סיסמת ההצפנה** | קובעת מה אפשר לקרוא | **לשום מקום** |

הן חייבות להיות **שונות**. אם תשתמש באותה סיסמה, ההצפנה מאבדת את משמעותה.

**אם תאבד את סיסמת ההצפנה, נתוני הענן אינם ניתנים לשחזור.** אין "שכחתי
סיסמה" — זה בדיוק מה שהופך את ההצפנה לאמיתית. שמור אותה במנהל סיסמאות.
הנתונים במכשיר ובגיבויים אינם מושפעים.

## הקמה

### 1. פרויקט

[console.firebase.google.com](https://console.firebase.google.com) ← Add project.
אפשר לכבות Google Analytics.

### 2. התחברות

Build ← Authentication ← Get started ← **Google** ← Enable.

תחת Settings ← **Authorized domains**, הוסף את הדומיין שבו האפליקציה
מתארחת (למשל `pinto1212121212-create.github.io`). בלי זה ההתחברות תיכשל.

### 3. מסד נתונים ואחסון

- Build ← **Firestore Database** ← Create database ← **Production mode**
- Build ← **Storage** ← Get started ← **Production mode**

"Production mode" חוסם הכל כברירת מחדל; הכללים שבתיקייה הזו יפתחו בדיוק
את מה שצריך.

### 4. פריסת הכללים

```bash
cd firebase
npx firebase-tools login
npx firebase-tools use --add          # בחר את הפרויקט שיצרת
npx firebase-tools deploy --only firestore:rules,storage:rules
```

⚠️ **אל תדלג על השלב הזה.** בלעדיו Firestore ו-Storage חסומים לגמרי.

### 5. חיבור האפליקציה

Project settings ← Your apps ← Web app. העתק את הערכים לבלוק `CLOUD`
בראש ה-script ב-`index.html`:

```js
const CLOUD = {
  apiKey:     'AIza...',
  authDomain: 'hanhac-uriel.firebaseapp.com',
  projectId:  'hanhac-uriel',
  bucket:     'hanhac-uriel.firebasestorage.app',
};
```

הערכים האלה **אינם סוד** ומיועדים להיות בקוד הלקוח. האבטחה נשענת על כללי
האבטחה ועל ההצפנה, לא על הסתרתם.

### 6. שימוש

טאב סיכום ← ☁️ סנכרון ענן ← התחבר עם Google ← הגדר סיסמת הצפנה.
במכשיר נוסף: אותם צעדים, והזנת סיסמת ההצפנה פעם אחת.

## מה נשמר ואיך

| מיקום | תוכן |
|---|---|
| `users/{uid}/keys/dek` | מפתח ההצפנה, עטוף בסיסמה שלך |
| `users/{uid}/entries/{id}` | רשומה מוצפנת — רק `iv` ו-`ct` |
| `users/{uid}/meta/state` | הגדרות וצ'קליסט, מוצפנים |
| `users/{uid}/files/{key}` | מטא-דאטה מוצפן של קובץ |
| Storage `users/{uid}/files/{key}` | הקבלה עצמה, בייטים מוצפנים |

**היררכיית המפתחות:** מפתח נתונים אקראי (DEK) מצפין את התוכן, והוא עצמו
נשמר עטוף במפתח שנגזר מסיסמת ההצפנה (PBKDF2, 600,000 איטרציות). כך שינוי
סיסמה עוטף מחדש מפתח אחד, במקום להצפין מחדש את כל הארכיון.

## הרצת האמולטור ובדיקות

```bash
npm run emulators      # בטרמינל נפרד
npm run test:cloud     # כללי אבטחה + סנכרון
```

`test/rules.mjs` מוודא שהכללים **חוסמים** את מה שצריך: משתמש אחר, שדה
טקסט גלוי, קובץ מעל 25MB, והעלאת JPEG לא מוצפן.

`test/cloud.mjs` בודק את הסנכרון מקצה לקצה — כולל שליפת המסמך הגולמי
מ-Firestore ווידוא שאין בו סכום, קטגוריה או הערה.

## פרטים

- **התנגשויות** נפתרות ב-last-write-wins לפי `updatedAt`. אם תערוך את אותה
  רשומה בשני מכשירים בין סנכרונים, המאוחר ינצח.
- **מחיקות** מתפשטות כ-tombstones: הרשומה מסומנת כמחוקה ולא מוסרת, אחרת
  היא הייתה חוזרת מהמכשיר השני בסנכרון הבא.
- **סנכרון אוטומטי** רץ 3 שניות אחרי כל שינוי, ויש גם כפתור ידני.
- **עלות:** בקנה מידה אישי השימוש נמצא בתוך המכסה החינמית של Firebase.
